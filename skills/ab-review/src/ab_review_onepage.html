SKILLab-review A/B 双角色多轮审阅-修改 · 自动闭环

Claude Code skill：A=执行修改，B=审阅挑刺。两者交替推进，每条意见都带依据链，直到 B 终审通过或达 3 轮上限。支持单进程自闭环与双终端隔离两种模式。触发 /ab-review <路径> 或自然语言含"AB审阅"；可被其他 skill 经 Skill() 调用。

1 流程：B 审阅 → A 决策修改 → 乒乓至终审

每轮两个角色的产出

B 在 b-round-N.md 每条意见指出：位置 / 理解障碍原因 / 修改方向。已说清楚处不得强行找茬。

A 在 a-round-N.md 对每条做可审计决策：

判定条件动作
改依据非空（命令+行号）in-place Edit
拒绝B 无代码/文档支撑注明理由，B 下轮可反驳
待验证有道理但无法核实标 【待验证】 交还

依据链让"A 是否真核对"可检查——"Grep rx_data line 87"是真核实，"经检查无误"是糊弄。

2 两种运行模式

默认模式 · 单进程自闭环

一个 Claude 在一次回答内演完 A/B，跑满 3 轮。

  • 触发：/ab-review doc.md 或自然语言"AB审阅：对 doc.md…"
  • 快、零配置；但 A/B 同一上下文，有"自己放过自己"风险

★ --split 双终端模式 · 真隔离

A/B 跑两个终端（可不同模型），靠标志文件 + 定时轮询自动乒乓，无需人工中转。

  • B 端：/ab-review doc.md --split --role b --init 后挂 /loop 2m
  • A 端：/loop 2m /ab-review doc.md --split --role a
  • 协调：.ab-review/state.json，turn 字段(b/a/done)即互斥锁
  • 每次唤醒幂等单步：该自己则干一步，否则速退不空耗

3 双终端协调机制（--split 核心）

4 亮点

★ 全自动闭环，零人工中转

默认模式一次回答跑满 3 轮；--split 模式两端 /loop 自动乒乓，B 写文件 A 自动读到，无需复制粘贴传话。

★ A/B 真隔离，可用不同模型

--split 让 A、B 跑独立进程独立上下文，B 不知 A 思路，A 无法"自己放过自己"。B 端可挂更强模型审，隔离强度远超单进程。

★ 可审计决策，判断过程可查

每条意见必带"依据/判定/理由"，依据必须可复现（命令+行号）。A 是否真核对一看便知，B 可对"拒绝"反驳、对"待验证"补证。

★ 事实优先，拒绝权对等

A 只能依据代码/文档已有事实改，不得臆造；B 无依据时 A 有权拒绝。双方都有约束：B 不得强行找茬，A 不得无依据盲改。

★ RTL 深度叠加 rtl-analyze

标准按 object_type 分流：doc→6 默认+5 硬件专项、Mode C；rtl→6 代码替代+5 代码专项、Mode B。Mode B/C 报告先落 modeB-round-N.md 再摘要入 b-round，整份报告不进对话，防多轮遗忘。

★ state 机固化，流程可回归

_ab_state.py 收敛原子写（flock+os.replace），turn 即互斥锁；配套 25 项断言自测脚本，改 state 逻辑后一键回归。
